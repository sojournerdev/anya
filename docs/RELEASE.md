# Release Guide

## Purpose

This guide defines the release path for Anya container images and Kubernetes resources.

## Ownership

The Anya project owns:

- Container image source and build definition.
- OCI registry publication.
- Kustomize resources under `deploy/k8s/`.
- Default security and resource settings.
- Compatibility requirements.
- Release validation.
- Release notes and rollback metadata.

Operators own deployment execution. They select approved image artifacts and environment values, manage registry access, perform upgrades, verify rollouts, and execute rollbacks.

## Release Artifacts

An approved release provides:

- An immutable container image.
- The image digest.
- Release notes.
- Supported environment values.
- Software bill of materials when generated by the release pipeline.
- Vulnerability results, provenance, and signatures when generated by the release pipeline.

The release identifies supported Kubernetes, NVIDIA driver, container runtime, and device-plugin versions.

## Image Policy

Production releases use immutable image tags or digests. The release process does not use `latest` for production deployment.

The image repository, package visibility, pull permissions, supported architectures, and retention policy are release properties.

## Kubernetes Resource Policy

The Kustomize resources define the supported Kubernetes deployment interface. They provide:

- Image reference substitution.
- Node selection and runtime configuration.
- HTTP and refresh configuration.
- Resource requests and limits.
- Liveness and readiness probes.
- Service exposure.
- Security context.
- Rolling update behavior.

The supported deployment path is the Kustomize overlay applied with `kubectl`. No Helm chart is currently shipped.

## Release Validation

The release validation path covers:

- Container image construction.
- Image vulnerability results when available.
- SBOM generation when available.
- Provenance and signature generation when available.
- Kustomize rendering.
- Kubernetes resource validation.
- Deployment, upgrade, and rollback behavior in a test cluster.
- Health, readiness, and state API behavior.
- Compatibility between the image and Kubernetes resources.

## Promotion

A release is promoted only after image, resource, and compatibility checks pass. The promoted image digest and resource revision are recorded in the release notes.

## Operator Handoff

The release package provides operators with:

- Image reference and digest.
- Required image-pull configuration.
- Kustomize overlay and deployment command.
- Supported environment values.
- Compatibility requirements.
- Installation, upgrade, and rollback instructions.
- Verification expectations.

## Rollback

A rollback restores a known-good image and Kustomize resource revision. Operators verify DaemonSet rollout, readiness, state freshness, and pod restart behavior after rollback.
